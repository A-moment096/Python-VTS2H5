# v1.2.0: VTK dataset conversion

Status: scope approved by the user on 2026-10-12; detailed implementation
plan approved and implemented; see `docs/v1.2.0-verification.md`.

## Outcome

Convert folders of common serial VTK datasets into compressed HDF5 files
and XDMF3 descriptors, preserving geometry, connectivity, point fields,
cell fields, and time steps. Keep the `vtk2h5` command and existing Python
entry points usable. Compression and read performance depend on the
dataset, compression algorithm, and reader; do not promise universal gains.

## Approaches

1. Add readers only, retaining the uniform-grid writer. This is small but
   supports only uniform structured datasets and would reject most VTU/VTP
   inputs. It does not meet the intended broad format support.
2. Normalize supported VTK datasets into explicit geometry families and
   extend HDF5/XDMF together. Recommended: preserves semantics, retains the
   compact existing uniform-grid layout, and adds no runtime dependency.
3. Convert everything into an unstructured mesh. This simplifies the output
   model but expands structured-grid connectivity and sacrifices storage
   efficiency. Do not use this as the default.

## Format scope

| Input | VTK dataset | Output representation |
| --- | --- | --- |
| `.vts` | StructuredGrid | Existing compact uniform layout when valid; otherwise explicit structured XYZ points |
| `.vti` | ImageData | Compact origin/spacing for axis-aligned images; explicit structured points for nonidentity direction matrices |
| `.vtr` | RectilinearGrid | Separate coordinate axes, including nonuniform spacing |
| `.vtu` | UnstructuredGrid | Explicit XYZ points and XDMF connectivity |
| `.vtp` | PolyData | Explicit XYZ points and XDMF connectivity |
| `.vtk` | Legacy dataset | Dispatch by actual dataset type to the same geometry families |

Support legacy ASCII and binary and XML ASCII, base64/appended, compressed,
and raw appended input through VTK readers. Do not parse entire XML files
with ElementTree as a prerequisite: raw appended payloads need not be valid
XML to a general-purpose parser.

Initial unstructured cell scope: vertex, polyvertex, line, polyline,
triangle, quad, polygon, tetrahedron, pyramid, wedge, and hexahedron.
Normalize pixel/voxel connectivity into quad/hexahedron ordering. Expand
triangle strips into triangles with matching duplicated cell fields. Expand
multi-point Polyvertex groups into individual vertices with repeated cell
fields for ParaView XDMF3 compatibility.
Use XDMF Mixed topology for heterogeneous cells with the required count
prefixes for variable-length cells. Reject unsupported higher-order and
polyhedron cells with the source filename and cell type; do not silently
linearize, discard cells, or resample data.

Defer parallel manifests (`.pvts`, `.pvti`, `.pvtr`, `.pvtu`, `.pvtp`),
multiblock (`.vtm`), collection manifests (`.pvd`), and changing meshes.
These need separate policies for pieces, blocks, and time metadata.
Treat `.vtd` as unspecified rather than guessing a reader.

## Reader and compatibility

Add `VTKReader`, choosing a VTK reader by case-insensitive extension and
checking the actual output type. Capture VTK ErrorEvent messages and error
codes; reject failed reads, empty geometry, invalid connectivity, unnamed
or duplicate fields, and unsupported nonnumeric arrays with actionable
messages. Enable all legacy scalar/vector/tensor/field arrays explicitly.

The normalized record includes geometry family, source dataset type,
point/cell counts, bounds, point/cell data dictionaries, and geometry payload.
Structured records retain XYZ dimensions and VTK's x-fastest tuple order.
Unstructured records carry XYZ points and encoded connectivity.
Preserve VTSReader and convert_vts_to_hdf5 compatibility entry points;
introduce convert_vtk_to_hdf5 as the generic API.

## HDF5 and XDMF

Retain the v1.1 uniform-grid file layout and ZYX field ordering. Add a
versioned geometry-family attribute for new representations. Keep geometry
at the file root and fields under `timeseries/step_N`.

Rectilinear output stores coordinate axes and uses rectilinear XDMF
topology/geometry. Explicit structured output stores points with XDMF
structured topology and XYZ geometry. Unstructured output stores points
and integer connectivity; fields have shapes `(tuples,)` or
`(tuples, components)` rather than structured ZYX shapes.

Derive descriptor dimensions, numeric types, precision, and references
from the actual stored datasets. Verify 1D/2D structured topology and
degenerate axes against ParaView rather than assuming 3D descriptors work
for every geometry family. Preserve float precision options, compression,
integer types, field priority, and relative HDF5 references.

Require unchanged geometry, connectivity, field names, shapes, and stored
types within a series. Mixed source extensions are allowed when their
normalized mesh and schema agree. Compare geometry payloads, not merely
grid dimensions.

## CLI and output safety

Discover supported extensions deterministically and case-insensitively.
Add repeatable `--format EXT` to select formats in folders containing
multiple exports of the same frames. Keep existing step-number extraction;
reject duplicate or nonincreasing time steps before writing outputs.
Update --info and verbose output to show dataset type and counts, with
dimensions only for structured datasets.

Write both outputs to temporary sibling files, validate the descriptor,
and publish only after conversion succeeds. On failure, close handles and
remove temporary files while preserving existing outputs. The descriptor
must refer to the final HDF5 filename, not its temporary name. Publishing
two files cannot be one atomic filesystem operation; handle replacement
failures with backups and restoration.

## Implementation sequence

1. Add generated VTK fixtures and reader tests covering all supported
   formats, encoding modes, legacy multiple arrays, and invalid inputs.
   Implement generic dispatch and normalization while retaining VTS APIs.
2. Extend geometry validation and HDF5 storage for rectilinear and explicit
   structured grids. Test nonuniform axes, curved grids, image extents and
   direction, negative spacing, degenerate axes, and unchanged v1.1 layout.
3. Implement unstructured connectivity encoding and HDF5 storage. Test
   every supported cell, mixed topology, pixel/voxel ordering, triangle
   strips, cell-field correspondence, and explicit unsupported-cell errors.
4. Extend XDMF generation for each geometry family. Check every referenced
   dataset, shape, type, precision, and point/cell association. Add optional
   ParaView round trips comparing coordinates, connectivity, and fields.
5. Integrate generic conversion into sequential and multiprocessing paths,
   add CLI format selection and generic info, and implement safe output
   publication. Test schema/mesh changes and failure preservation.
6. Update README, usage guide, changelog, package description, and both
   version declarations to 1.2.0. Document the supported cell/format matrix
   and limitations. Run full tests, lint, formatting, and package build.

## Acceptance criteria

- Existing VTS regressions pass, retaining compact uniform output behavior.
- Every listed format converts in sequential and multiprocessing modes.
- Geometry and numeric fields match source datasets after reading outputs.
- Mixed cell topology preserves connectivity and cell data order.
- Unsupported input fails explicitly without replacing existing output.
- Compression, precision conversion, field priority, and multi-folder
  behavior work across geometry families.
- ParaView round-trip results are reported separately from structural XML
  and HDF5 checks; unavailable ParaView is an explicit validation gap.
- A buildable v1.2.0 package and documented compatibility limits are ready.

Unrelated smaller features remain outside this scope until specified.
