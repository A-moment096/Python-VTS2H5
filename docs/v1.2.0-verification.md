# v1.2.0 verification

## Project rename

The project, Python package, CLI, wheel, and source archive now use
`vtk2h5`. Imports use `from vtk2h5 import ...`; the command is `vtk2h5`.
There is no old-name package or console alias. VTS-specific reader and
conversion function names remain available under the new package.
The hosted repository URLs retain their existing location.

After the rename, the standard suite passed **338 tests** (79 optional
ParaView tests skipped), and three representative ParaView round trips
passed using `VTK2H5_PVPYTHON`. The 58 reader tests also passed with
coverage configured for the new package. The full 79-case ParaView result
below was obtained before the package rename.

The new wheel's metadata, namespace, and console entry point were checked.
It imports in isolation and converts all nine generated series.
The local editable install reports `vtk2h5 1.2.0`.

Implementation is available on `codex/v1.2.0-vtk-formats` in the working
tree for user review. Supplied data and the user's `.gitignore` change
were retained. No release was published.

## Automated checks

- Latest standard suite: **338 passed**, 79 optional ParaView tests skipped
  in that run. Command: `python -m pytest tests --cov=vtk2h5 --cov-report=term-missing -q`.
- Actual ParaView 6.2.0 suite: **79 passed**, including every singleton-axis position and one-point grids. Command: `python -m pytest tests/test_vtk_paraview.py tests/test_paraview_roundtrip.py --no-cov -q` with `VTK2H5_PVPYTHON` set.
- Combined verification: **417 tests passed** across the standard and actual ParaView runs.
- `black --check src`, `ruff check src`, and `git diff --check` pass.
- `uv lock` updates the package metadata to 1.2.0; `uv build` produces the
  wheel and source distribution under `dist/`.
- The final wheel installs into an isolated target and imports from that
  target. All nine generated series convert with the installed package;
  legacy active scalars and component metadata also read successfully.
- The source archive includes the sample generator and its fixture module.

An independent reviewer found truncated legacy ASCII and duplicate field
declaration issues. The fixes reject VTK data-reading warnings and check
serialized declarations before VTK merges arrays. Regression tests cover
legacy ASCII/binary, XML ASCII/raw-appended, active scalar/vector/tensor
arrays, and component/information metadata. The focused re-review reported
no remaining blocker.

## Supplied datasets

All 303 supplied frames were converted and every stored field tuple and
reconstructed coordinate was compared with the source. Each output has
101 time-step groups. Results are in `data/v1.2.0-results`.

| Series | Original bytes | HDF5 bytes | Reduction |
| --- | ---: | ---: | ---: |
| VTS scalars | 18,101,328 | 10,629,239 | 41.28% |
| VTS geometry-only `vec3_variables` | 3,630,546 | 94,488 | 97.40% |
| Legacy VTK | 7,809,300 | 2,066,514 | 73.54% |

These reductions compare source bytes with HDF5 bytes at default gzip
level 4; descriptor bytes are additional. The files named `vec3_variables`
have empty PointData and CellData, so they do not establish vector-field
coverage. Generated fixtures exercise actual vector and tensor values.
Reading-speed improvements have not been benchmarked.

## Generated datasets and behavior

`python scripts/generate_test_data.py OUTPUT_DIRECTORY` creates two frames
for uniform and curved structured grids, images, rotated images,
nonuniform rectilinear grids, unstructured meshes, PolyData, comprehensive
mixed cells, and legacy structured data. It refuses to overwrite files.
Samples and converted pairs are available in `data/generated-v1.2.0`.

Higher-order cells, polyhedra, changing meshes, parallel manifests,
multiblock, and collection manifests remain outside this release.
Multi-point Polyvertex groups expand into individual vertices, and strips
expand into triangles; source cell fields repeat for each output cell.
These normalizations were chosen to preserve geometry and values while
avoiding a ParaView Mixed Polyvertex element-count failure.

The scalar and vector-named VTS source series must be selected separately
because their filenames contain duplicate step numbers. Conversion of
the whole supplied VTS folder as one series is intentionally rejected.
